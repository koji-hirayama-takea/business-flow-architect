## エグゼクティブサマリー

### 数字で見る効果

| 指標 | Before(導入前) | After(導入後) | 効果 |
|---|---|---|---|
| 朝のチーム把握時間 | **30-45 分**(毎朝) | **5 分** | 約 8 倍効率化 |
| 把握できるメンバー数 | **5-6 名** | **15 名全員** | 約 2.5-3 倍 |
| 異変検知のスピード | SOS 後(遅) | **🟡 アラートで早期** | 退職予兆を事前察知 |

### 顧客像(本ヒアリングから推測)

- プレシリーズ A SaaS スタートアップで 15 名のプロダクトチームを統括する PM
- 責任範囲:メンバーのパフォーマンス + メンタル + 進捗を全て見る必要
- Slack + Notion + GitHub + Meet の 4 ツール環境(フルリモート)
- 「**15 名全員を見落とさず見られる安心感**」が最大の価値
- 対話を大事にするマネージャータイプ

→ **PM / EM / マネージャー向けプロダクト紹介のリファレンスとして最適**

## 2. 根本原因の分類

### 2.1 「人(People)」起因

| 課題 | 原因 |
|---|---|
| C-001 | PM 1 人で 15 名分の情報を頭の中で組み立てる必要(認知限界) |
| C-002, C-004 | 人間が 15 名の活動傾向を網羅的に追えない |

→ TeamLog は「**マネージャーの認知拡張**」として作用。

### 2.2 「プロセス(Process)」起因

| 課題 | 原因 |
|---|---|
| C-001 | Slack スクロール + Notion 確認 + GitHub 確認の手動横串プロセス |
| C-003 | 1on1 前の事前準備プロセスが無い(時間取れない) |
| C-005 | 月次経営報告のデータ集計プロセスが無い |

→ TeamLog は「**自動化 + 統合**」として作用。

### 2.3 「文化(Culture)」起因

| 課題 | 原因 |
|---|---|
| C-002, C-004 | 「メンバーが SOS を出すまで気づけない」受動的マネジメント文化 |

→ TeamLog は「**能動的なシグナル検出**」として文化転換を促す。

## 4. 感情価値が最大の事例: C-002 / C-004 退職予兆検知

### 4.1 Before → After

```
Before(従来のマネジメント)
  ↓
メンバーが家族の介護で疲弊
  ↓
我慢して仕事を続ける(表面上は問題なさそう)
  ↓
ある日突然「辞めたい」と SOS → 既に手遅れ

After(TeamLog アラート)
  ↓
TeamLog がパターン検知:
  Slack 投稿 -60% / Notion 更新 0 件 / GitHub commit 5 日前
  ↓
朝のサマリーに 🟡 注意メンバーとして表示
  ↓
PM が即座に Slack DM「ちょっと話せる時間ある?」
  ↓
15 分話して 家族介護で疲弊 が判明
  ↓
業務調整 + 周囲からの声がけで救済
  ↓
退職を未然防止
```

→ **数字に出ない、しかし TeamLog の最大価値**

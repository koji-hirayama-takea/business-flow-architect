# 例: TeamLog プロダクト概要 — PM / マネージャー 業務フロー(架空 / プロダクト紹介)

このフォルダは、business-flow-architect の **TeamLog プロダクト紹介(PM 視点)** のリファレンス実例です。

特定企業のヒアリング事例ではなく、**TeamLog プロダクトを PM / マネージャー業務フローとして説明する**ための業務記述書 + drawio + 課題分析 一式です。`templates/業務フロー図テンプレート.drawio` の構造に準拠(開始 → P-XXX → 終了 / 判断ひし形 / F-XXX / S-XXX / 矢印は source/target)。

## 用途

- マネージャー向けプロダクト説明資料の業務フロー化リファレンス
- 「PM / マネージャー視点でプロダクトを使うとどうなるか」を スイムレーン + 判断ひし形を含む業務フロー図で表現したサンプル
- 8 プロセスのプロダクト紹介フロー構造のリファレンス

## 想定設定(架空)

| 項目 | 値 |
|---|---|
| 会社 | 株式会社グラフィックパス(架空) |
| 規模 | PM が プロダクトチーム 15 名(エンジニア / デザイナー / ビジネス)を統括 |
| フェーズ | プレシリーズ A、TeamLog 導入後 3 ヶ月 |
| 働き方 | フルリモート |
| TeamLog 連携 | Slack + Notion + Meet 字幕拡張 + GitHub |

```
└── output/

    ├── TeamLogプロダクト概要-PM用_業務フロー図_v1.0_20260528.drawio
    └── TeamLogプロダクト概要-PM用_課題発生ポイント分析_v1.0_20260528.md
```

## このサンプルが示す要素

- ✅ P-001〜P-008 の **8 プロセス**(朝のチームステータス → 注意メンバー検知 → 詳細分析 → 1on1 or 声がけ)
- ✅ F-001〜F-003 の 3 ファイル
- ✅ S-001〜S-005 の 5 システム連携(うち S-005 は TeamLog MCP レーン)
- ✅ C-001〜C-005 の 5 課題発生ポイント(導入前の課題、全件 ✅ TeamLog で解決済み)
- ✅ **4 レーン構成**(PM / メンバー / TeamLog / 連携ツール)
- ✅ **判断ひし形 2 つ**(P-003 注意メンバーいる? / P-006 1on1 設定 or 声がけ?)

## 利用条件

学習目的の参照のみに使用してください。
**マスキング解除・再配布・SNS への転載** は禁止です(架空ケースですが、リアル感が強いため誤認回避目的)。

business-flow-architect スキルを使う際の **「マネージャー向けプロダクト紹介フロー」型のリファレンス** として参照可能です。

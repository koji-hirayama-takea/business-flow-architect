# 例: 経費精算プロセス(架空)

このフォルダは、business-flow-architect の **リファレンス実例** です。AI が業務記述書 + drawio + 課題発生ポイント分析を生成するときに、「**この粒度・密度で書く**」基準として参照します。

## 想定設定(架空)

| 項目 | 値 |
|---|---|
| 会社 | 株式会社サンプル(架空) |
| ヒアリング相手 | 経理部 田中マネージャー(架空) |
| 対象業務 | メンバー個人立替の月次経費精算プロセス |
| ヒアリング日 | 2026-05-27 |

## ファイル構成

```
経費精算プロセス/
├── README.md                                              ← 本ファイル
├── input/
│   └── hearing-sample.md                                  ← 架空のヒアリング文字起こし
└── output/
    ├── 経費精算プロセス_業務記述書_v1.0_20260527.md         ← スキルが生成する想定の業務記述書
    ├── 経費精算プロセス_業務フロー図_v1.0_20260527.drawio   ← スキルが生成する想定の drawio
    └── 経費精算プロセス_課題発生ポイント分析_v1.0_20260527.md ← スキルが生成する想定の独立分析
```

## このサンプルが示す要素

- ✅ P-001〜P-008 の 8 プロセス(時系列順)
- ✅ F-001〜F-005 の 5 ファイル
- ✅ S-001〜S-002 の 2 システム連携
- ✅ C-001〜C-005 の 5 課題発生ポイント
- ✅ 自社プロダクトでの解決可能性判定(✅ 可能 / ⚠️ 間接的 / ❌ 不可)
- ✅ **7 レーン構成**(社外 / メンバー / 上長 / 経理担当 / 経理マネージャー / 社内システム / 社外サービス)— 使わないミドルオフィス系 2 レーンは**削除して詰めた**
- ✅ 通常フロー(実線)+ システム連携(破線)
- ✅ 課題吹き出し(C-XXX)を該当プロセスの近くに配置

## AI への指示(SKILL.md / prompts 経由で参照)

新しいヒアリングを処理するとき、AI は本サンプルを開いて以下を学習してください:

1. **業務記述書の粒度** — 「活動内容」をどれくらい具体的に書くか
2. **顧客の言葉の引用** — 課題深掘りでヒアリング相手の発言をどう引用するか(逐語引用 + 文脈補足)
3. **解決可能性判定の判断基準** — ✅/⚠️/❌ をどの粒度で分けるか
4. **drawio のレイアウト** — 各要素をどのレーンに、どの座標で配置するか
5. **C-XXX の配置** — どのプロセスにどう紐付けるか

このサンプルを上回る粒度で出力してください(これは「最低限の基準」です)。

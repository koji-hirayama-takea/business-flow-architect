# examples/ — リファレンス実例集

スキルが実際にどんな成果物を生成するかを示すリファレンス実例集。AI が業務記述書 + drawio + 課題発生ポイント分析を生成するとき、**「この粒度・密度で書く」基準** として参照される。

## 含まれる実例

### [経費精算プロセス/](経費精算プロセス/) — リファレンスケース

**設定**: 株式会社サンプル(架空) 経理部 田中マネージャーへのヒアリング → メンバー個人立替の月次経費精算プロセスを分析

**含まれる成果物**:
- 架空のヒアリング文字起こし(`input/hearing-sample.md`、約 2000 字)
- 業務記述書(P-001〜P-008、F-001〜F-005、S-001〜S-002、C-001〜C-005 のフルセット)
- 業務フロー図(`.drawio`、9 レーン構造で 8 プロセス + 5 ファイル + 5 課題吹き出し + 2 システム連携)
- 課題発生ポイント分析(独立 .md、5 件の課題ごとに引用・根本原因・解決可能性判定)

このサンプルは **AI が出力する 3 ファイルの「最低限の基準」** です。実ヒアリングを処理するときは、このサンプルを上回る粒度で出力します。

## AI への指示(SKILL.md / prompts 経由で参照)

新しいヒアリングを処理するとき、AI は本サンプルを開いて以下を学習する:

1. **業務記述書の粒度** — 「活動内容」をどれくらい具体的に書くか
2. **顧客の言葉の引用** — 課題深掘りでヒアリング相手の発言をどう引用するか(逐語引用 + 文脈補足)
3. **解決可能性判定の判断基準** — ✅/⚠️/❌ をどの粒度で分けるか
4. **drawio のレイアウト** — 各要素をどのレーンに、どの座標で配置するか
5. **C-XXX の配置** — どのプロセスにどう紐付けるか
6. **エグゼクティブサマリー** — 課題発生ポイント分析の冒頭で、自社提案ターゲットをどう絞るか

## 実例の構造規約

各実例は、以下のディレクトリ構造で揃える:

```
[ケース名]/
├── README.md                                     ← ケースの設定・含まれる要素の説明
├── input/
│   └── hearing-sample.md                         ← ヒアリング文字起こし
└── output/
    ├── [ケース名]_業務記述書_v1.0_YYYYMMDD.md
    ├── [ケース名]_業務フロー図_v1.0_YYYYMMDD.drawio
    └── [ケース名]_課題発生ポイント分析_v1.0_YYYYMMDD.md
```

## 利用条件

これらの実例は、**学習目的の参照** のみに使用してください。
**マスキング解除・再配布・SNS への転載** は禁止です(架空ケースですが、想定設定はリアル感が強いため誤認回避目的)。

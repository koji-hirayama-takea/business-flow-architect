# 04_ Claude Code 実行手順

Claude Code と drawio MCP を使って、ヒアリング文字起こし 1 件から業務記述書 + drawio + 課題発生ポイント分析の 3 点セットを 5 分で生成する手順。

---

## 前提

- Claude Code がインストール済み (`claude` コマンドが使える)
- drawio MCP が `~/.claude.json` or プロジェクト直下の `.mcp.json` に登録済み
- 本テンプレ集 (`業務フローAIアシスタント-drawio-mcp/`) がプロジェクト内にある
- ヒアリング文字起こしファイル (`.md` または `.txt`) が手元にある

---

## drawio MCP の `.mcp.json` 登録例

プロジェクト直下の `.mcp.json` に以下を追記(まだなら):

```json
{
  "mcpServers": {
    "drawio": {
      "command": "npx",
      "args": ["-y", "@drawio/mcp"]
    }
  }
}
```

(MCP サーバー名が違う場合は、各自の環境に合わせて読み替え)

---

## 標準フロー (3 ステップ)

### Step 1: プロジェクト構成を整える

```bash
# 任意のプロジェクトディレクトリで
mkdir -p ./業務フロー
ls ./業務フローAIアシスタント-drawio-mcp/   # 本テンプレ集が見えること
```

ヒアリング文字起こしを `hearings/[相手社名]_MTG_YYYYMMDD.md` 等に配置。

```
project-root/
├── .mcp.json                                 # drawio MCP 登録
├── 業務フローAIアシスタント-drawio-mcp/      # 本テンプレ集
├── hearings/
│   └── customer-interview_2026-05-15.md     # ヒアリング文字起こし
└── 業務フロー/                                # 生成物の出力先 (Claude Code が自動で作る)
```

### Step 2: Claude Code に投げる

`claude code` を起動して、以下を投げます (1 行)。

```
business-flow-architect スキルで、@hearings/customer-interview_2026-05-15.md の業務フロー一式を作って
```

(または起動キーワード「業務フロー作って」「会議を drawio にして」など)

Claude Code が自動でやること:

1. SKILL.md と base-prompt.md を読む
2. ヒアリング文字起こしを読み込み、プロセス名を確定 + プロセスを時系列に抽出
3. **[プロセス名] のサブディレクトリを作成**: `mkdir -p {出力先}/[プロセス名]/`
4. **業務記述書 .md** を生成 → `{出力先}/[プロセス名]/[プロセス名]_業務記述書_v1.0_YYYYMMDD.md`
5. **drawio XML** を生成 → `{出力先}/[プロセス名]/[プロセス名]_業務フロー図_v1.0_YYYYMMDD.drawio`
6. drawio MCP の `open_drawio_xml` を呼ぶ → ブラウザで drawio.com がプレビューを開く
7. **課題発生ポイント分析 .md** を生成 → `{出力先}/[プロセス名]/[プロセス名]_課題発生ポイント分析_v1.0_YYYYMMDD.md`
8. P-XXX / F-XXX / S-XXX / C-XXX が業務記述書と drawio で一致しているかチェック → 結果を報告

体感: **5 分以内**で サブディレクトリ + 3 ファイル + ブラウザプレビューまで完了。

出力例(出力先 = `./outputs/`、ヒアリングから抽出されたプロセス名 = `経費精算プロセス`):

```
./outputs/
└── 経費精算プロセス/
    ├── 経費精算プロセス_業務記述書_v1.0_20260528.md
    ├── 経費精算プロセス_業務フロー図_v1.0_20260528.drawio
    └── 経費精算プロセス_課題発生ポイント分析_v1.0_20260528.md
```

複数のヒアリングを処理する場合、それぞれのプロセス名でサブディレクトリが分かれます:

```
./outputs/
├── 経費精算プロセス/
├── メンバー状況把握/
├── 採用プロセス/
└── ...
```

### Step 3: ブラウザで微調整 → 保存

drawio.com が自動で開くので、必要に応じて:

1. プロセス要素の位置をドラッグで微調整 (時系列は上から下を維持)
2. ファイル付箋の位置を関連 P-XXX の右側に揃える
3. 課題吹き出し (⚠️) の位置を該当 P-XXX の近くに寄せる
4. `File > Save` で `.drawio` ファイルとして保存 (Claude Code が出力したパスに上書き)

## よくあるトラブルと対処

### Q1. drawio MCP が登録されていない / 動かない

A. 一旦 MCP なしで .drawio ファイルだけ生成して、手動で drawio.com にアップロードしてください。
ベースプロンプトの中の「Step 5: drawio MCP の `open_drawio_xml` で...」を削除すれば、ファイル生成のみで完了します。

### Q2. ヒアリングが長すぎてコンテキストを溢れる

A. ヒアリング .md を以下のように事前要約 → 渡す:
- `### プロセス情報` セクション (運用フロー、関連ツール、報告体系)
- `### 課題` セクション (顧客の言葉そのまま)
- `### システム` セクション (使用ツール一覧)

Claude Code に丸投げするより、事前に構造化した方が精度が上がります。

### Q3. 同じヒアリングで毎回違う結果が出る (再現性問題)

A. 以下を試す:
- Claude Code のセッションを新規 (`claude code --new-session`)
- ベースプロンプトを最新版に更新
- `temperature=0.3` 相当の指示を追加 ("出力は冪等で、再現性を優先してください" と末尾に添える)

### Q4. プロセスが多すぎて 1 枚の drawio に収まらない

A. ベースプロンプトに「最大プロセス数: 10」を指定する。
それ以上は、機能単位で分割した複数の業務フロー図 (.drawio) を生成させる。

### Q5. 課題発生ポイント (C-XXX) が薄い

A. ヒアリング文字起こしに **顧客の言葉の直接引用** が含まれていることを確認。
「具体的なエピソード:」「課題が発生する頻度:」「課題の深刻度 (顧客の言葉で):」のセクションがヒアリング側にあると、C-XXX 分析の精度が大きく上がります。

## 出力例の確認方法

生成された 3 ファイルを以下で確認:

```bash
# 業務記述書 (Markdown)
cat ./業務フロー/メンバー状況把握_業務記述書_v1.0_20260527.md

# 業務フロー図 (drawio、テキスト)
head -50 ./業務フロー/メンバー状況把握_業務フロー図_v1.0_20260527.drawio

# 課題発生ポイント分析
cat ./業務フロー/メンバー状況把握_課題発生ポイント分析_v1.0_20260527.md
```

すべての P-XXX が業務記述書と drawio で一致していること、C-XXX が両方に出てくることを目視確認。

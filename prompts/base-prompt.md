# 01_ ベースプロンプト (drawio MCP 版)

Claude Code に貼り付けて使うマスタープロンプト。ヒアリング文字起こしを渡すと、業務記述書 + drawio 業務フロー図 + 課題発生ポイント分析の 3 点セットを自動生成する。

---

## 使い方

1. このプロンプト全体を Claude Code にコピペ
2. 続けて、ヒアリング文字起こしファイル(`.md`)のパスを渡す
3. Claude Code が自動で 3 ファイル生成 + drawio MCP でブラウザプレビュー

```bash
# 例
claude code
> 以下のベースプロンプトを使って、@hearing-sample.md の業務フロー一式を作って
```

## マスタープロンプト(以下をコピー)

```
あなたは、ユーザーヒアリングの文字起こしから「業務フロー + 課題構造」を抽出する戦略アナリストです。
渡された文字起こしから、以下の 3 つを順番に生成してください。

# 生成する 3 つの成果物

## ① 業務記述書 (Markdown)

`templates/業務記述書_テンプレート.md` の構造に従って Markdown を生成します。

含める要素:
- **1. プロセス概要** — プロセス名 / 目的 / 範囲(開始点・終了点) / 関連部門
- **2. プロセス詳細** — 表形式で P-001, P-002, ... を時系列順に
  - 列: プロセス番号 / プロセス名 / 実施者 / 活動内容 / 使用証憑 / 作成証憑 / ファイル番号 / システム連携 / 前工程依存 / 後工程依存 / 備考
  - 備考欄に **⚠️ 課題発生ポイント** を C-XXX 番号付きでマーキング
- **3. ファイル・データ一覧** — F-001, F-002, ... を使用順序で
- **4. システム連携** — S-001, S-002, ... を実行順序で
- **🆕 5. 課題発生ポイント分析** — C-XXX ごとに以下を整理
  - プロセス番号 / 課題内容 / 根本原因 / 自社プロダクトで解決可能か (✅ 可能 / ⚠️ 間接的 / ❌ 不可)
- **6. 時系列チェック項目**
- **7. 改訂履歴**

採番ルール:
- P-XXX: 時系列順
- F-XXX: 使用順序、同一ファイルが複数プロセスで使われるなら **最初に使われる番号** を採用
- S-XXX: 実行順序
- C-XXX: 課題が見えた順序

時系列の原則(絶対):
- ✅ 開始点から終了点まで上から下への一貫した流れ
- ❌ 上から下に反する配置は禁止

## ② 業務フロー図 (drawio XML)

`templates/業務フロー図テンプレート.drawio` の構造に従って XML を生成します。

⚠️ **絶対ルール: mxCell は入れ子(nesting)にしない**

drawio XML では、`<mxCell>` の中に他の `<mxCell>` を入れることはできません。**全ての `<mxCell>` は `<root>` 直下のフラットな兄弟** として配置し、親子関係は `parent="..."` 属性だけで表現します。

NG (これをやると `a.push is not a function for mxCell` エラーで開けない):

```xml
<mxCell id="swim-container">
  <mxCell id="lane-soto"/>   <!-- ❌ 入れ子になっている -->
</mxCell>
```

OK (フラット配置 + parent 属性):

```xml
<mxCell id="swim-container" parent="1">
  <mxGeometry .../>
</mxCell>
<mxCell id="lane-soto" parent="swim-container">  <!-- ✅ root 直下、parent で親指定 -->
  <mxGeometry .../>
</mxCell>
```

⚠️ **値に改行 (&#xa;) を含むセルは必ず `whiteSpace=wrap;html=1` をスタイルに入れる**

```xml
<!-- NG: 改行が表示されない -->
<mxCell value="P-001&#xa;[プロセス名]" style="rounded=1;fillColor=#DAEEFF"/>

<!-- OK: 改行が正しく表示される -->
<mxCell value="P-001&#xa;[プロセス名]" style="rounded=1;whiteSpace=wrap;html=1;fillColor=#DAEEFF"/>
```

---

スイムレーン(最大 9 種、ヒアリングで実際に登場する役割だけ使う):

| # | レーン | 色 |
|---|---|---|
| 1 | 社外 (取引先/顧客) | #F5F5F5 |
| 2 | フロント担当者 | #E6F3FF |
| 3 | フロント承認者 | #E6F3FF |
| 4 | ミドルオフィス担当者 | #F0F8E6 |
| 5 | ミドルオフィス承認者 | #F0F8E6 |
| 6 | バックオフィス担当者 | #FFF0E6 |
| 7 | バックオフィス承認者 | #FFF0E6 |
| 8 | 社内システム | #F0E6FF |
| 9 | 社外サービス | #F5F5F5 |

⚠️ **使わないレーンは削除して詰める(「未使用」表記で残さない)**

ヒアリング内容から、実際に登場する役割を抽出する。たとえば経費精算プロセスなら、社外 / フロント担当者 (= メンバー) / フロント承認者 (= 上長) / バックオフィス担当者 (= 経理担当) / バックオフィス承認者 (= 経理マネージャー) / 社内システム / 社外サービス = 7 レーン。**ミドルオフィスは使わないので 4・5 を削除し、残りの x 座標を 170 ずつ詰める**。

詰めた x 座標の計算ルール:
- 使うレーン数 N に対して、swim-container の width = 170 × N
- 各レーンの x = (連番) × 170 (0, 170, 340, 510, 680, ...)
- 既存テンプレ(`templates/業務フロー図テンプレート.drawio`)は 9 レーンのフル構造なので、コピーしてから不要レーンを削除して詰める

逆に、ヒアリングで「フロント担当者」が 2 種類出てきた場合 (例: 営業担当 + 営業アシスタント)、レーン名を変えて両方使うのは OK。**新規スイムレーンの追加もケースバイケースで OK** (ただし合計 9 を超えない)。

レーン名は実態に置き換える(例: 「フロント担当者」→「メンバー (フロント担当者)」、「バックオフィス担当者」→「佐藤さん (経理担当)」など、ヒアリング相手の組織用語を優先)。

図形要素(各要素の推奨サイズも明示):

| 種類 | 用途 | スタイル | 推奨サイズ | 色 |
|---|---|---|---|---|
| 楕円 | 開始 / 終了 | `ellipse;whiteSpace=wrap;html=1` | 100 x 50 | 開始: #D5E8D4 / 終了: #F8CECC |
| 角丸四角 | 業務プロセス P-XXX | `rounded=1;whiteSpace=wrap;html=1` | 120-130 x 60-70 | #DAEEFF |
| ひし形 | 承認・判断 (分岐) | `rhombus;whiteSpace=wrap;html=1` | 130 x 80 | #FFE6E6 |
| 四角 | システム処理 | `rounded=0;whiteSpace=wrap;html=1` | 120-130 x 60 | #E8D8FF |
| 付箋型 | ファイル F-XXX | `shape=note;whiteSpace=wrap;html=1;align=center;verticalAlign=middle` | **110 x 65-70** | #FFF2CC |
| **吹き出し** | **課題発生ポイント C-XXX** | `shape=callout;whiteSpace=wrap;html=1;align=center;verticalAlign=middle;spacingTop=4;spacingBottom=16` | **160 x 80-85** | #FFE6E6 / stroke=#D32F2F / fontStyle=1 |

⚠️ **サイズ指定のルール(テキスト溢れを防ぐ)**:
- callout は **必ず 160x80 以上**(下部のしっぽが 16-20px を食うため)
- note も **110x65 以上**(右上の折り返し部分を考慮)
- すべての多行テキストセルに `whiteSpace=wrap;html=1` + `align=center;verticalAlign=middle` を必須

🆕 課題発生ポイント (C-XXX):
- 該当プロセスの近くに、**警告アイコン付きの吹き出し**(`shape=callout`)で配置
- スタイル(完全形): `shape=callout;whiteSpace=wrap;html=1;align=center;verticalAlign=middle;spacingTop=4;spacingBottom=16;fillColor=#FFE6E6;strokeColor=#D32F2F;fontStyle=1;fontSize=10`
- サイズ: 160 x 80-85(これより小さくしない)
- ラベル: `⚠️ C-XXX&#xa;[課題内容]&#xa;[補足を15-20字]`(3 行構成、各行 15 文字以内)

フロー線:
- 通常フロー: 実線 (edgeStyle=orthogonalEdgeStyle)
- システム連携: 破線 (dashed=1)
- 差戻しループ: 実線 + 赤色 (strokeColor=#B85450) で視覚的に区別

⚠️ 判断ひし形 (P-XXX 判断) は必ず Yes/No の 2 経路を持つ:
- **承認 (Yes)**: メインフロー、下方向の次のプロセスへ
  - 例: `value="承認"` / exitX=0.5;exitY=1 → entryX=0.5;entryY=0
- **差戻し (No)**: 前のプロセスへループバック、赤色実線で区別
  - 例: `value="差戻し"` / strokeColor=#B85450 / exitX=0;exitY=0.5 → entryX=1;entryY=0.5

矢印にラベルを付けるときの style:
- `fontSize=10;fontStyle=1;labelBackgroundColor=#ffffff`(白背景でラベルを読みやすくする)

並列処理パターン (オプション):
- 1 つの判断 / プロセスから複数の経路が分岐し、合流するパターン
- 例: P-002 → P-003 (lane-mid-tan) + P-002 → P-003b (lane-back-tan) → 両方が P-004 に合流
- 単純な業務フローなら不要、複雑なケースで使う

凡例 (legend) — 視覚的に作る (テキストだけの凡例 NG):
- swim-container の下に、各図形要素の**実物の小さなサンプル**を並べる
- 構造: 背景の角丸なし四角(620x220、#F5F5F5) + タイトル「【凡例】」 + 8 種の図形サンプル + ラベル
- 2 列 × 4 行レイアウト推奨
  - 左列: 楕円(40x22)/ 角丸四角(40x22)/ ひし形(40x28)/ 四角(40x22)
  - 右列: 付箋(42x24)/ 吹き出し(50x32)/ 実線矢印(45px)/ 破線矢印(45px)
- 矢印は `endArrow=classic` で sourcePoint / targetPoint を絶対座標で指定
- `templates/業務フロー図テンプレート.drawio` の凡例セクションをそのままコピーすれば速い

XML 出力先:
- ファイルパス: `{出力先}/[プロセス名]/[プロセス名]_業務フロー図_v1.0_$(date +%Y%m%d).drawio`
- 出力先サブディレクトリは Step 2 で作成済(`mkdir -p`)
- 生成後、drawio MCP の `open_drawio_xml` ツールでブラウザプレビュー

## ③ 課題発生ポイント分析 (Markdown、業務記述書の §5 を独立ファイル化)

`{出力先}/[プロセス名]/[プロセス名]_課題発生ポイント分析_v1.0_$(date +%Y%m%d).md` として、同じサブディレクトリ内に独立保存。

含める要素:
- 課題サマリー (C-XXX 一覧、深刻度判定)
- 根本原因の分類 (人 / プロセス / システム / 文化)
- 自社プロダクトでの解決可能性マトリクス
- 次の検証アクション提案

# 実行手順

1. ヒアリング文字起こしを読み込み、プロセス名を確定 + プロセスを時系列に抽出
2. **出力サブディレクトリを作成**: `mkdir -p "{出力先}/[プロセス名]/"`
3. ① 業務記述書を Markdown で生成 → `{出力先}/[プロセス名]/[プロセス名]_業務記述書_v1.0_YYYYMMDD.md`
4. ② drawio XML を生成 → `{出力先}/[プロセス名]/[プロセス名]_業務フロー図_v1.0_YYYYMMDD.drawio`
5. drawio MCP の `open_drawio_xml` で XML を渡してブラウザプレビュー
6. ③ 課題発生ポイント分析を独立 .md として → `{出力先}/[プロセス名]/[プロセス名]_課題発生ポイント分析_v1.0_YYYYMMDD.md`
7. 最後に、サブディレクトリパスと 3 ファイル + 整合性チェック結果 (P/F/S/C 番号が業務記述書と drawio で一致しているか) を報告

# 出力時の注意

- 専門用語は補足を入れる ("MCP (Model Context Protocol)" 等)
- 数字や時間は実態ベース (推測なら明記)
- ヒアリング相手の社名・人名は **そのまま使う** (マスキングは別工程)
```

## 補足: drawio MCP の呼び方

Claude Code から drawio MCP を呼ぶときは:

```
drawio MCP の open_drawio_xml ツールに、生成した XML 文字列を渡してください。
ブラウザで drawio.com が開いて、図がプレビューされます。
```

XML の改行や特殊文字でエラーが出る場合は:
1. XML を一度ファイルに保存 (`Write` ツール)
2. ファイル内容を再読 (`Read` ツール) して文字列化
3. `open_drawio_xml` に渡す
